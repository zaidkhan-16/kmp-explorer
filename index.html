01

Introduction

What is string matching, and why does KMP matter?

~3 min
💡

Real-World Scenario

Imagine searching for the word ABABCABAB inside a large document containing millions of characters.

A basic algorithm compares characters one by one. Whenever it encounters a mismatch, it may repeat comparisons unnecessarily.

KMP solves this by remembering information from previous comparisons — so it never looks at the same character twice.

1

What is string matching?

Given a text string and a pattern string, find all positions where the pattern occurs inside the text. This is fundamental to search engines, text editors, DNA analysis, and network security.

2

What is the naive algorithm?

Try the pattern at every position in the text. At each position, compare characters one by one. If all match, record the position. Otherwise, shift the pattern by one character and restart from scratch.

3

Why is naive matching inefficient?

When a mismatch occurs after several matching characters, the naive algorithm forgets everything it just learned and re-examines the same characters. In the worst case, this results in O(n × m) comparisons.

4

What problem does KMP solve?

KMP preprocesses the pattern into a failure function (LPS array) that tells it exactly where to resume after a mismatch — achieving O(n + m) time with zero wasted comparisons on the text.

Naive vs KMP — At a Glance

Aspect Naive Algorithm KMP Algorithm
Comparison strategy May repeat comparisons Reuses previous information
Worst-case time O(n × m) O(n + m)
Preprocessing None Builds an LPS array in O(m)
Text pointer behavior May move backwards Never moves backwards

Understanding the LPS Array

The secret engine behind KMP's efficiency.

~7 min

What is LPS?

LPS stands for Longest Proper Prefix which is also a Suffix.

For every position i in the pattern, LPS[i] tells us the length of the longest proper prefix of the substring pattern[0..i] that is also a suffix of that substring.

📌

A proper prefix is a prefix that is not the entire string. For example, the proper prefixes of ABC are "", "A", and "AB" (but not "ABC").

How Is LPS Computed?

1

Start with LPS[0] = 0 (a single character has no proper prefix/suffix).

2

Maintain a variable length tracking the length of the previous longest prefix-suffix. Start at 0.

3

For each position i from 1 to m−1:

  • If pattern[i] == pattern[length]: increment length, set LPS[i] = length.
  • If they don't match and length ≠ 0: set length = LPS[length − 1] (fall back) and retry without advancing i.
  • If they don't match and length == 0: set LPS[i] = 0, move to next i.

05

Python Implementation

Complete, commented code you can run today.

~5 min
Python 
def compute_lps(pattern):
    """Build the Longest Proper Prefix-Suffix array."""
    m = len(pattern)
    lps = [0] * m          # LPS array, initialized to all zeros
    length = 0              # Length of the previous longest prefix-suffix
    i = 1                   # Start from index 1 (LPS[0] is always 0)

    while i < m:
        if pattern[i] == pattern[length]:
            # Characters match → extend the current prefix-suffix
            length += 1
            lps[i] = length
            i += 1
        elif length != 0:
            # Mismatch after some matches → fall back using LPS
            # Don't increment i — try again with shorter prefix
            length = lps[length - 1]
        else:
            # No match and no fallback → LPS[i] = 0
            lps[i] = 0
            i += 1

    return lps

How This Works

m — Length of the pattern string.
lps — The result array. lps[i] stores the length of the longest proper prefix of pattern[0..i] that is also a suffix.
length — Tracks the length of the current matching prefix-suffix. Acts as a pointer into the pattern.
i — Scans through the pattern from position 1 onward.

The key insight: when there's a mismatch at pattern[i] vs pattern[length], we don't restart from zero. Instead, we fall back to lps[length - 1] — the next best prefix-suffix — and try again. This is the same "remembering" trick KMP uses during the actual search.

Python 
def kmp_search(text, pattern):
    """Find all occurrences of pattern in text using KMP."""
    n = len(text)
    m = len(pattern)
    if m == 0:
        return []

    lps = compute_lps(pattern)  # Preprocess: build the LPS array
    i = 0  # Pointer for text — never moves backwards!
    j = 0  # Pointer for pattern — falls back using LPS
    result = []

    while i < n:
        if text[i] == pattern[j]:
            # Characters match → advance both pointers
            i += 1
            j += 1
        else:
            if j != 0:
                # Mismatch after partial match → use LPS to skip
                j = lps[j - 1]
            else:
                # Mismatch at first character → advance text pointer
                i += 1

        if j == m:
            # Full pattern matched! Record the starting index.
            result.append(i - j)
            j = lps[j - 1]  # Continue searching for more matches

    return result

How This Works

i — Text pointer. Moves only forward, never backwards. This is why KMP achieves O(n) scanning.
j — Pattern pointer. When a mismatch occurs, it falls back using lps[j-1] instead of resetting to 0.
result — Collects all starting indices where the pattern is found.

When j == m (we've matched all pattern characters), we record the match at index i - j and set j = lps[j-1] to continue searching for overlapping matches.

def kmp_search(text, pattern):
    """Find all occurrences of pattern in text using KMP."""
    n = len(text)
    m = len(pattern)
    if m == 0:
        return []
    lps = compute_lps(pattern)
    i = 0
    j = 0
    result = []
    while i < n:
        if text[i] == pattern[j]:
            i += 1

            else:
                i += 1
        if j == m:
            result.append(i - j)
            j = lps[j - 1]
    return result

pattern = "ABABCABAB"

06

Complexity Analysis

Why KMP is efficient — a rigorous look.

~3 min
Operation Time Complexity
LPS constructionO(m)
Pattern searchingO(n)
TotalO(n + m)
Auxiliary spaceO(m)

Why Is This True?

→

The text pointer i never moves backwards

In each iteration of the search loop, either i advances (match or j == 0 mismatch) or j decreases via the LPS fallback. Since i only moves forward through the text of length n, the text is scanned in at most O(n) steps.

↩

The pattern pointer j falls back using LPS

When a mismatch occurs, j doesn't reset to 0. It falls back to LPS[j−1], which is always strictly less than j. The total number of fallbacks across the entire search is bounded because j can only fall back as many times as it has been incremented — giving an amortized O(n) total.

∀

Every character is processed a bounded number of times

Each character in the text is compared at most a constant number of times. The amortized analysis shows that the total comparisons across all positions sum to at most 2n, since each increment of i is paired with at most one fallback sequence.

💾

The LPS array requires O(m) additional memory

The only extra space KMP needs is the LPS array of size m (the pattern length). The search itself uses constant additional variables (i, j), making the total auxiliary space O(m).

Naive vs KMP: Growth Comparison

As input size grows, the difference between O(n×m) and O(n+m) becomes dramatic.
